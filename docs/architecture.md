# Architecture

Mosa is one Next.js App Router application. Server Components read the SQLite catalog through `src/features/catalog/queries.ts`. Client Components own forms, favorites, navigation, and the video element. Route Handlers receive browser mutations. Drizzle schemas and migrations live under `src/db/`. Provider adapters normalize Xtream or M3U entries before insertion; playback resolves stream URLs at request time. The demo provider is isolated by provider ID.

The local database and generated encryption key live in ignored `data/`. Start the application bound to loopback; it has no remote-user authentication.

Catalog queries count and group the full enabled-provider dataset on the server; the browser receives only one page or five results per search group. Live TV selects and replaces one player at a time; source resolution is separate from catalog import. Xtream series fetch episode details lazily on first detail visit and persist episode IDs to preserve progress. Provider refresh updates known metadata in place, preserving media IDs, favorites, and history; reconciliation of missing items remains future work.

The active provider ID and user preferences live in the existing `preferences` table; selecting one provider scopes catalog, search, favorites shown, playback resolution, and recent history without deleting other providers. Settings uses section tabs so the desktop viewport stays fixed; only the active section scrolls when its contents exceed the available height. Media controls remain in the existing Shaka/native video integration. PWA installation serves a manifest and icons but deliberately does not cache private playback URLs, credentials, or video.

For authorized Stalker/MAG portals, a provider-issued MAC is encrypted as part of its configuration. Connection checking requires both a handshake token and an accepted profile; a handshake token alone is not considered authentication. A compatible portal can supply a bulk live-channel catalog and resolve one temporary channel link at selection time. Authenticated server requests block cross-origin redirects, retain the existing remote URL restrictions, and never cache tokens or relay video. The Mosa installation UUID is not used for provider authentication. Unsupported portal variants fail rather than silently importing fictitious content.

The device QR contains only this installation's random UUID, not credentials or a login URL. Scanning it cannot authenticate another person. Real cross-device pairing would require explicit user approval, expiring one-time codes, authenticated endpoints, per-user authorization, TLS and a protected server reachable by both devices. The bundled local service remains bound to loopback; deploying it as-is publicly would expose private IPTV credentials and user data.

The playback shell is mounted at the locale layout boundary so watch-page video remains alive while navigating after entering floating mode. Live TV transfers to that shell when the floating button is clicked; the channel restarts on handoff. Browser Picture-in-Picture is available only where supported and requires a user gesture; the in-app floating player has separate pause and fullscreen controls.
